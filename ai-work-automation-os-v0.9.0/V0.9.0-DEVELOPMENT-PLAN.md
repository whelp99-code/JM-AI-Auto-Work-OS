# AI Work Automation OS v0.9.0 개발계획서

## 1. 개발 목표

v0.8.0은 기능을 빠르게 확장하면서 Prisma 모델이 44개까지 증가했다. 같은 업무 상태가 Mission, Graph, Organization, Evaluation, Approval, Deliverable, 여러 Event 테이블에 중복 저장되어 로컬 운영·백업·복원·화면 조회가 복잡해졌다.

v0.9.0의 목표는 다음과 같다.

1. 물리 DB를 44개 모델에서 **18개 canonical table**로 직접 축소한다.
2. 별도 Runtime Ledger와 Projection DB를 병행하지 않는다.
3. 기존 v0.8.0 데이터를 자동 백업하고 무손실에 가깝게 변환한다.
4. Backend Runtime, API, UI/UX, 사용자 Workflow가 새 DB를 직접 사용하게 한다.
5. Local-First·단일 사용자·SQLite·Inline 원칙을 유지한다.
6. 외부 행동·검증·승인·감사의 안전 경계를 유지한다.
7. 실패 시 원본 DB를 변경하지 않고 명시적 롤백을 제공한다.

## 2. 비범위

v0.9.0에서 다음은 구현하지 않는다.

- 멀티사용자·멀티테넌트
- Supabase Auth·RLS·PGMQ 활성화
- 분산 Worker·대규모 병렬 실행
- 실제 이메일·배포·결제 adapter
- 완전자율 외부 행동
- ProofGraph 통합 개발 Runtime

## 4. 데이터 모델 계획

```text
Organization : workspace, org_unit, role, agent
Mission      : mission, mission_run, work_item
Workflow     : workflow_step, workflow_transition
Quality      : review, approval
AI Council   : council_session, council_message, decision_record
Delivery     : artifact, external_effect
Operations   : event_log, file_asset
```

### 핵심 통합 규칙

- Company/Department/Team/Mission Organization → `org_unit`
- AgentRole/RoleDefinition → `role`
- AgentInstance → `agent`
- GraphNodeRun/Dispatch/RoleInvocation → `workflow_step`
- Graph route/edge → `workflow_transition`
- Evaluation/Independent QA/Failure Packet → `review`
- Executive/Workflow/Staffing/Team/Effect Approval → `approval`
- Mission/Graph/Organization/Audit events → `event_log`
- Deliverable/Council Artifact → `artifact`
- USD Float → integer micros

## 5. DB 리빌드 계획

```text
현재 DB schema 감지
→ dry-run
→ v0.8.0 원본 backup
→ read-only source open
→ 임시 v0.9.0 DB 생성
→ transaction 데이터 변환
→ exact 18 tables 검사
→ FK/integrity/schema version 검사
→ 원본을 .v0.8.0 sidecar로 이동
→ 임시 DB를 현재 DB 경로로 atomic rename
→ migration report 저장
```

오류가 발생하면 임시 DB를 삭제하고 원본을 유지한다. Swap 도중 오류가 나면 sidecar를 원래 경로로 복구한다.

## 6. Runtime 계획

### Mission
- 자연어 목표·예산·성공 조건 입력
- 업무 유형·위험도 추론
- MissionRun idempotency

### Organization
- Executive Manager
- 업무 유형별 Department·Team
- Producer와 Independent Verifier 분리

### Workflow
- Budget → Triage → Research/Plan → Risk Gate
- RED 업무 Human Approval
- Execute → Independent Verify
- Synthesize → Final Verify → Final Gate → Finalize

### External Effect
- 요청은 `external_effect` 원장에 기록
- 승인 전 실행 금지
- 실제 adapter가 없으므로 자동 실행 금지

## 7. UI/UX 계획

```text
Command Center
→ Mission 생성
→ 통합 Mission Workspace
   ├─ Overview
   ├─ AI 조직
   ├─ Workflow
   ├─ 승인
   ├─ AI Council
   ├─ 검증·증거
   ├─ 산출물
   └─ 감사 기록
```

별도 `/settings/database`에서 schema version, DB 경로, 정확한 18개 테이블, row count, integrity 상태를 확인한다.

## 8. 완료 기준

- 물리 테이블 정확히 18개
- v0.8.0 핵심 데이터 이관
- dry-run 무변경
- unknown schema fail-closed
- migration 재실행 no-op
- v0.8.0 rollback 가능
- Producer/Verifier 분리
- 승인 replay 차단
- Verify/Final Gate 우회 불가
- ExternalEffect 자동 실행 없음
- Local loopback-only
- 새 UI가 새 DB를 직접 조회
- offline 검증 전부 통과
- 대상 장비에서 `npm install`, `npm test`, `npm run build` 통과
